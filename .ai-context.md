# AI Context: OrderApi

This file provides a concise description of the project structure, design patterns, and dependencies to optimize context and token usage for future AI prompts.

## 🚀 Tech Stack & Dependencies
- **Core**: .NET 10.0 Web API (Minimal APIs)
- **Database**: Entity Framework Core (`10.0.10`) targeting MS SQL Server.
- **CQRS & Messaging**: MediatR (`14.2.0`) for internal command/query dispatching and in-memory event publishing (`INotification`).
- **Validation**: FluentValidation (`12.1.1`) integrated via MediatR Pipeline Behaviors.
- **RabbitMQ**: RabbitMQ — `IRabbitMqProducer` / `RabbitMqProducer` publishes events to RabbitMQ exchanges as JSON. Config keys: `RabbitMq__Host` (e.g., `localhost` or `rabbitmq`) and `RabbitMq__Port` (default is 5672).
- **Infrastructure**: Docker Compose with RabbitMQ, RabbitMQ Management UI, and OrderApi.

## 🏛️ Architecture Overview
The application follows a clean CQRS (Command Query Responsibility Segregation) architecture handled via MediatR.

### Core Flows:
1. **Validation Pipeline**:
   - `ValidationBehavior<TRequest, TResponse>` intercepts all MediatR requests.
   - If any `AbstractValidator<TRequest>` is found, validation runs automatically.
   - Failures throw a `FluentValidation.ValidationException`, which is caught at the API layer (returning `Results.ValidationProblem`).
2. **Commands (Writes)**:
   - Command records implement `IRequest<TResponse>`.
   - Handlers implement `IRequestHandler<TCommand, TResponse>`.
   - Creation of resources triggers an event dispatched via MediatR's `IPublisher.Publish()`.
3. **Queries (Reads)**:
   - Query records implement `IRequest<TResponse>`.
   - Handlers implement `IRequestHandler<TQuery, TResponse>`.
4. **Events (Pub/Sub)**:
   - Events implement `INotification`.
   - Handlers implement `INotificationHandler<TNotification>`. Currently, `ConsoleOrderCreatedEventHandler` logs events to stdout.
